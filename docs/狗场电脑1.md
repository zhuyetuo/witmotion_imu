# 狗场电脑1 · 操作备忘

这台管 **1 / 2 / 3 号单间**：那三间的摄像头（3 路），加那三间的 6 个项圈。

| 机位 | 房间 | 项圈 | 狗 |
|---|---|---|---|
| cam1 | 1 号单间 | imu9 / imu10 | 小白（比熊） |
| cam2 | 2 号单间 | imu11 / imu12 | 流浪柯基 |
| cam3 | 3 号单间 | imu13 / imu14 | 流浪小金毛 |

每只狗两个项圈轮换充电，**两个都在这台机器上录** —— 不管今天戴哪一个，都有自己房间的画面配着。

> 4/5/6 号单间和 7 号公共区（天花板）在**狗场电脑2** 上，别在这台找。

---

## 每天开录

```bash
cd ~/witmotion_imu && git pull
SITE=狗场1 ./record_multicam.sh
```

就这两行。窗口别关，它会一直录到你停为止，按整点自动切文件。

- 想看画面：在这个终端敲 `p` + 回车（再敲一次关掉，开着大概掉四成帧率）
- 停止录制：敲 `q` + 回车，或者 Ctrl+C
- 日志：`logs/record_multicam_<日期>.log`，按天切、留 30 天。出问题回头翻这个

## 装机之后只做一次：核对摄像头索引

**这一步不做的话不会报错**，会安安静静录一整天，然后 2 号房间的画面存成了 cam1 —— 平台是按 camN 判房间的，从此 A 房间的狗配着 B 房间的画面。

```bash
SITE=狗场1 ./record_multicam.sh --probe
```

打印出来是 `cam1 (摄像头 0)`、`cam2 (摄像头 1)` 这样。分不清哪路对哪间就开预览看画面：

```bash
PREVIEW=1 DEBUG=1 SITE=狗场1 ./record_multicam.sh
```

（`DEBUG=1` = 只看画面，什么都不存）画面左上角标着 cam1/cam2/cam3。

对不上就改 `sites/狗场1.env` 里 `CAMERAS` 的**第二列**（第一列是房间号，别动）：

```
CAMERAS="
1  0   # 1 号单间   ← 第二列是这台机器上的摄像头索引，只改这个
2  1   # 2 号单间
3  2   # 3 号单间
"
```

核对一次就行，之后除非重插 USB 口。

### 顺手做的（可选）

```bash
echo 狗场1 > sites/.current
```

写了之后 `SITE=狗场1` 可以省掉不写。配自动归档的计划任务时**必须**写（计划任务没法每次手敲 `SITE=`）。这个文件不进版本库，两台各写各的。

## 清理暂存文件

一次录制完，目录里除了配对好的文件，还剩一堆中间产物（未配对的原始视频、合并的总 IMU 流水、meta 等）。

```bash
# 先看要删什么，不动手
SITE=狗场1 ./cleanup_gouchang.sh -n ~/witmotion_imu/data/multicam_multiimu/2026_9_17_gouchang

# 确认没问题再删
SITE=狗场1 ./cleanup_gouchang.sh    ~/witmotion_imu/data/multicam_multiimu/2026_9_17_gouchang
```

日期换成实际那天。**这台没有公共区那路**（cam7 在电脑2 上），脚本会自己从场地配置读出来，不用手敲 `--shared-cam none`；开头会打一行 `场地 狗场1：公用机位 = （没有）`，看到这行就对了。

## 传 NAS

```bash
SITE=狗场1 ./daily_archive.sh              # 处理昨天 + 补传之前失败的
SITE=狗场1 ./daily_archive.sh --today      # 确定已经收工了才用
DRY_RUN=1 SITE=狗场1 ./daily_archive.sh    # 只打印要做什么
```

它**不删原始数据**：先建暂存目录（硬链接，不占额外空间），传完 NAS 再把暂存删掉，删的是链接。NAS 连不上（VPN 断了）只记一笔跳过，本地什么都不动，下次自动补传。

这台传上去的是每路一份视频 + 6 个项圈各一份 CSV。轮换的第二个项圈（10/12/14）只传 CSV —— 它配的是同一路摄像头的**同一段画面**，传两遍就是每小时白传 1.5GB。

## 出问题先看这里

**某个设备一直 MISSING** — 正常现象，狗趴着压住项圈就会断，会自动重连。日志里搜这几行：

```
[imu11] 连接断开（信号问题），尝试自动重连...
[imu11] 仍未收到广播，已等待 N 分钟
[imu11] 收不到广播已久，直接按 MAC 盲连一次: ...
[imu11] 盲连成功: ...
```

看到「盲连成功」说明救回来了。一直失败多半是那个项圈没电 / 在充电座上 —— 充电中的设备也在广播，扫得到不代表戴在狗身上。

**敲 `python` / `conda` / `pip` 说 command not found** — **这是正常的，不是环境没装好。**

`setup_windows.sh` 把 miniconda 装在仓库的 `.tools/miniconda3` 下，而且**故意不加进 PATH**（那份 conda 跟着仓库走，加进 PATH 的话仓库一挪一删 PATH 就指向空目录，还会悄悄接管这台机器上所有命令行的 python）。

所以：

- **录制、清理、归档这些脚本都不受影响** —— 它们自己会找到仓库里那份 python。
- 要在终端里手敲 `python xxx.py` 的话，先来一行：

```bash
cd ~/witmotion_imu
source ./activate_env.sh
python -V          # 验证一下，应该打印 Python 3.13.x
```

- **千万别在 Anaconda Prompt 里 `pip install -r requirements.txt`** —— 那会装进系统那份 Anaconda，而录制用的是仓库里那份，装了也是白装。要装依赖就跑：

```bash
cd ~/witmotion_imu && ./setup_windows.sh
```
它会把 miniconda、ffmpeg、pip 依赖、电源设置一次装齐，装过的自动跳过。

真要确认仓库这份装没装好：

```bash
ls ~/witmotion_imu/.tools/miniconda3/python.exe    # 有这个文件就是装好了
```

**想确认哪个项圈真戴在狗身上** —— 一次晃一只狗的项圈，跑 8 秒看哪个报「有活动」：

```bash
source ./activate_env.sh          # 新开的终端要先来这一行，见下面「python 找不到」
python check_device_worn.py --imu wit=DC:32:39:07:0A:3D --imu wit=CB:DC:DC:40:3D:D1 --duration 8
```

**只想临时少开一路做对比** — 直接改命令行，别改场地文件：

```bash
CAMS="0 1" SITE=狗场1 ./record_multicam.sh
```

脚本会自动把指向没开那路的配对去掉，并在启动时打一行提示。

## 别做的事

- **别在这台跑 `SITE=狗场2`** —— 两台会去抢同一批项圈，BLE 一个从机同时只能连一个主机，抢起来两边都断断续续。
- **别改 `CAMERAS` 的第一列** —— 那是房间号，全场地共用一套（cam4 永远是 4 号单间，不管它在哪台机器上）。改了平台就判错房间。
- **别为了换班去改场地文件** —— 两个轮换组都在 `DEVICES` 里一起录，不需要 `USE_STANDBY`。
